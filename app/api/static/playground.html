Data chat

This service answers questions for signed-in users of the application that embeds it. It has no sign-in of its own except a local development playground, which mints sessions with no host-app key -- so it is off by default, refuses any caller that is not on this machine, and should never be enabled anywhere real. 

WIDGET_DEV_PLAYGROUND=true python -m app.api.main

💬 Data chat gateway

Beyond this page the service has no user interface — it answers questions and serves the embeddable widget. The chat your users see lives on your page, or on the sample application.

EndpointWho calls it
GET /healthzanything
GET /widget.jsthe browser, via a script tag
POST /v1/sessionyour server — needs a host-app key
POST /v1/identity/lookupyour server — email → role
GET /v1/methe browser — who this session is
POST /v1/askthe browser, with a session token
POST /v1/ask/streamthe browser — Server-Sent Events
GET /v1/files/{id}the browser — a generated report

Embedding it

One script tag, plus one endpoint on your backend that mints a session for whoever is logged in there. The browser never holds the host-app key, which is why it cannot choose its own data scope.

Full guide: docs/web-plugin.md. A working host application, with email one-time-code sign-in: examples/supabase-app (npm start --prefix examples/supabase-app, then open port 3000).
